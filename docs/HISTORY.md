# 작업 이력 (2026-07-23 ~ 11-05)

## 배경

원본 `onvif_srvd`는 PTZ를 개루프로 제어한다 — 모터 텔레메트리를 읽지 않고 목표만 던진다.
이 하드웨어는 전류 센싱이 없는 FOC 모터라 **막힌 방향으로 목표가 잡히면 무한정 토크를 걸어 과열**된다.
아래는 그 문제를 잡아가는 과정에서 배운 것과 만든 것의 기록이다.

원인 조사에서 드러난 사실:

- 소프트 한계(±2.8)가 실제 물리 스톱보다 넓어 스톱에 눌린 채 대기하는 구간 존재

### 07-27 ~ 07-29 · 스톨 가드 v5 → v8

목표: **"모터가 열받아 고장나지 않는 것"이 1순위, 그 다음이 "pan/tilt가 당연히 잘 되는 것"**.

| 버전 | 내용 | 결과 |
|---|---|---|
| v5 | 램프 복원 + 기본 스톨 가드 | ±2π 프레임에서 오탐 → tilt 오작동 |
| v6/v7 | 절대범위 폴트 래치 추가 | 프레임 어긋남에 오발동해 tilt를 잠금 ("tilt에 힘이 없어") |
| **v8** | wrap 인식 가드로 재설계 | 검증 통과 |

v8 구성:
- 오차 계산 전면 wrap 보정 (`wrapd(x) = remainderf(x, 2π)`), 절대범위 폴트 래치 제거
- 2단계 재무장 (`R` → 1s → `S` → 1s → `T` 스트림, 벤더 타이밍)
- 폭주 감지 (역방향 누적 W / 미수렴 주행 A) → 파일 래치
- 반복 스톨 3회/60초 → 10분 잠금 (자동 해제)
- 한계 학습 (동일 지점 2회 확인, 30분 TTL, 0.05 rad 백오프 주차)
- 모든 단발 이동을 램프로 전환

다중 에이전트 설계 검토와 적대적 코드리뷰로 다음 결함을 배포 전에 발견·수정:
재무장 시 목표가 0.0으로 고정, 이동 유실, 잠금 해제 불가, 한계 오학습, 정상 이동의 지연을 스톨로 오판.

`.28`에서 검증 완료 — 일반 조작 / 손으로 막기(2초 후 재무장) / 한계까지 밀기 전부 정상.

### 08-12 ~ 08-13 · rangeonly 변종 + tilt 폭주 사고

- 요청에 따라 **각도제한만 있고 스톨가드 없는 변종** 추가 (`ONVIF_SIMPLE_RANGE=1`)
- `.205`에 배포. 이후 tilt가 **뒤로 2회전 폭주**

원인: `position.txt`를 `0 0 0`으로 설정 → **tilt 0은 엔코더 랩 경계** →
부팅 복원 램프가 어긋난 프레임에서 계산되어 다회전 이동으로 번역됨.
이후 tilt가 90° 밖 자세로 이탈하고, 그 자세에서 재정렬이 반복되며 오류 고착.

**소프트웨어 각도제한은 정상 작동했다** (모든 명령이 0~90° 안).
하지만 각도제한은 *명령 공간*만 제한할 뿐 *시작 자세*에는 개입할 수 없다.
→ **물리 스토퍼 설치로 근본 해결.** 상세: [incidents/INCIDENT-205-tilt-over90.md](incidents/INCIDENT-205-tilt-over90.md)

### 08-13 · 수동 제어 도구

폭주 대응 중 `tools/` 스크립트를 만들면서 시행착오를 겪었고, 여기서 결정적 사실을 확인했다.

벤더의 `pantilt.py`는 되는데 내가 만든 건 안 움직였다. 차이는 세 가지였다:

1. **같은 값을 반복 전송하면 안 움직인다.** 값이 연속으로 변하는 램프여야 한다
2. **arming(`R`→1s→`S`→1s)이 필요하다.** 토크가 없으면 아무리 보내도 무반응
3. **tilt 스텝이 작으면 정지마찰을 못 이긴다.** pan 0.05 / tilt 0.2가 검증값

또한 초기 버전이 매 이동마다 `R`을 보내 "팍팍" 튀었다 — `R`은 리셋이라 재정렬을 유발한다.
최종적으로 `pantilt.py`의 레시피를 그대로 따르는 형태로 정착.
