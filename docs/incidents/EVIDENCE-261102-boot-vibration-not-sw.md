# ptz018 부팅 시 모터 떨림 — SW 원인 배제 근거

작성일: 2026-11-02 · 대상: ptz018 (MK3-xxxxxxxx) · 관련: [INCIDENT-261027](INCIDENT-261027-boot-motor-jerk.md), [INCIDENT-261029](INCIDENT-261029-boot-vibration-after-update.md)

## 결론

**현재 남아 있는 부팅 떨림은 Pi 측 SW(onvif_srvd 등)의 명령 문제가 아니라, 모터 MCU(펌웨어)의 기동 후 자체 동작과 기구/전원 조건에서 발생한다.**

- Pi는 부팅마다 벤더 규정 초기화 명령 `R → 1s → S`를 **1회만, 매번 동일한 타이밍으로** 보낸다. 부팅 중 이동 명령(`T`)은 0건.
- **같은 명령에 대해 떨림이 났다 안 났다 한다** → 차이는 명령 바깥(기구 자세·전원·MCU 동작)에서 생긴다.
- 떨림은 `S` 이후 MCU가 **스스로** 목표 0,0으로 이동하는 구간(특히 전원 OFF 동안 처진 틸트를 들어 올리는 구간)에서 발생한다.
- 10/27 SW 원인(R/S 4~5회 중복 전송)은 이미 수정·검증 완료 상태이며 현재도 유지되고 있다.

## 근거

### 근거 1. Pi가 보내는 명령은 부팅마다 동일 (MCU 출력 로그)

부팅 초기부터 모터 MCU 출력을 **읽기 전용**으로 기록하는 로거(`motor-log.service`, `/var/log/motor-log/`)로 확인.
MCU는 `R`을 받으면 재부팅 배너를, `S`를 받으면 `MOT: Init`을, `T`를 받으면 `Target angle: ...`을 출력하므로 받은 명령을 역으로 확인할 수 있다.

| 부팅 (11/02) | R 수신(배너) | S 수신(MOT Init) | 토크 인가 | Ready | 부팅 중 T | 현장 관찰 |
|---|---|---|---|---|---|---|
| 50cedda3 (콜드) | 8.8s | ~9.7s | ~10.2s | 10.8s | 0 | **떨림 없음**, 꽂고 약 18초 후 0,0 |
| a4d711ee (콜드) | 8.7s | 9.8s | 10.3s | 10.8s | 0 | **떨림 6~7초** |
| b7b47c66 (콜드) | 8.70s | 9.72s | 10.23s | 10.73s | 0 | **떨림 약 10초**, 틸트가 0으로 들리면서 동시 발생 |

(시각은 리눅스 부팅 기준 경과초. 10/30·11/02 오전 부팅 로그도 동일 시퀀스 ±0.1초.
50cedda3·a4d711ee는 로거 2개가 동시에 읽어 일부 줄이 깨졌으나 시퀀스 위치는 동일.)

→ **떨린 부팅과 안 떨린 부팅의 Pi 명령이 동일.** SW가 원인이면 명령이 달라야 한다.

### 근거 2. 명령이 없으면 움직임도 없음, 명령은 1회뿐 (10/27)

| 테스트 | 결과 |
|---|---|
| 콜드 부팅, onvif 기동 완전 차단(R/S 0회) | 모터 움직임 **전혀 없음** |
| 수정 전(부팅 중 R/S 4~5회) | 들썩 3회 + 떨림 → SW 원인, **수정 완료** |
| 수정 후(R/S 1회) 다수 콜드부팅/재부팅 | 들썩 1회(0,0 이동), 떨림 없음 — 현장 확인 |

→ 움직임의 계기는 `S`(모터 기동)이며, 이는 제품 동작에 반드시 필요한 벤더 규정 명령이다.
기동 이후 **어떻게 움직이는지(가감속, 토크, 안착)는 MCU 펌웨어가 결정**하며 Pi는 관여하지 않는다.

### 근거 3. SW 업데이트가 모터 명령 경로를 바꾸지 않음 (10/29)

| 항목 | 10/27(떨림 없음) | 10/29 이후(떨림 재발) |
|---|---|---|
| onvif_srvd 바이너리 | md5 `448443cd` | md5 `448443cd` (**동일**) |
| 부팅 중 onvif 기동 횟수 | 1회 | 1회 |
| dispatcher(90-onvif-restart) | 수정본 `b3402ad2` | `b3402ad2` (**동일**), 부팅 7회 모두 "재시작 생략" |
| 시리얼 쓰기 프로세스 | onvif_srvd만 | onvif_srvd만 (다른 로거는 O_RDONLY) |
| 시리얼 설정 | — | raw, echo off (수신 데이터가 MCU로 되돌아가지 않음) |

### 근거 4. 떨림 정도가 전원에 따라 달라짐

- 일반 PoE: 떨림 길어짐 / PoE++: 짧아짐 (10/29 현장 관찰).
- Pi 측 전압 저하 기록 없음(`throttled=0x0`, 5V 정상) → Pi 동작에는 영향 없음.
- SW 명령은 전원 종류와 무관하게 동일하므로, **전원(모터 토크 여유)에 따라 결과가 바뀌는 것은 하드웨어/펌웨어 특성**이다.

### 근거 5. 떨림이 MCU의 자체 이동 구간과 일치

- 11/02 b7b47c66: 전원 OFF 동안 틸트가 처진 상태(약 90°) → 토크 인가("딱딱" 소리, 10.2s) → MCU가 스스로 틸트를 0으로 들어 올리는 동안 약 10초 떨림.
- 이 구간에 Pi가 보낸 명령은 없음(근거 1).
- MCU는 `S` 직후 현재 위치와 무관하게 목표 0,0으로 바로 이동한다(소프트 스타트 없음). 중력 부하를 거슬러 큰 각도를 들어 올릴 때 토크(전압 제한)가 모자라면 헌팅/진동이 날 수 있는 구조.

## 펌웨어/기기 측 확인 사항

| 항목 | 현황 |
|---|---|
| 펌웨어 | **PAN `v2.3.0-manual` / TILT `v1.0.6` — 축별로 다름.** PAN은 수동 빌드 커스텀 버전 |
| PAN 설정 | 전압 제한 8.0 V, 속도 PID 6/5/0, 각도 P 20, 속도 제한 3.0, EEPROM 저장값 없음(기본값) |
| 기동 동작 | `S` 후 즉시 목표 0 이동, 소프트 스타트 없음 |
| 상태 조회 | "기동(arm) 여부" 조회 명령 없음. TILT는 `V`만 응답 → Pi에서 상태 확인 후 R/S 생략 불가 |
| 기구 | 전원 OFF 시 틸트가 자중으로 처짐 → 콜드부팅마다 큰 각도 들어 올림 필요 |

## Pi SW로 할 수 있는 것 / 없는 것

| | 내용 |
|---|---|
| 가능 | 펌웨어 버전(`V`) 확인·로그. 모터 전원이 살아 있는 재시작(`sudo reboot`, onvif 재시작)에서 R/S 생략 → **단, 펌웨어에 상태 조회 명령 추가가 선행돼야 함** |
| 불가 | 콜드부팅 시 떨림 제거 — `S`는 필수이고, 이후 이동 방식은 MCU 펌웨어가 결정 |

## 남은 확인 (원인 확정용)

1. 전원 OFF 상태에서 틸트를 손으로 0° 근처로 받친 채 콜드부팅 → 떨림이 없으면 "처진 틸트 들어 올리기" 원인 확정.
2. 정상 유닛과 PAN/TILT 펌웨어 버전·보정값 비교(`V`, `I`) — ptz020은 현장 출고로 불가, 다른 유닛 필요.
3. 펌웨어 측: 기동 시 소프트 스타트(현재 위치 → 0 천천히 이동), 상태 조회 명령 추가, 축별 펌웨어 버전 통일 검토.
