# PTZ 장애 개선 보고 — tilt 90° 초과 상태 기동 문제 (poelidar-2707-001, <field-unit-205>)

작성일: 2026-08-13

## 1. 요약

tilt 축이 **90°를 넘어간 자세에서 시스템이 기동(정렬)되면** 엔코더 보고 프레임과 FOC 센서 정렬이 잘못 잡혀, 이후 모든 각도 명령이 오동작(역방향 반응·다회전 폭주·무토크)하는 연쇄 장애가 발생했다.
소프트웨어 대증 조치와 함께 **물리적 스토퍼 설치(tilt 90° 초과 기구적으로 차단)** 로 근본 원인을 제거했다.

## 2. 증상 (발생 순서)

| 순서 | 증상 |
|---|---|
| 1 | onvif 부팅 위치복원 시 tilt가 **뒤로 약 2회전** 하는 폭주 |
| 2 | 이후 tilt 각도 명령에 대해 엔코더가 **반대 방향으로 반응** (cmd ↑ → cur ↓), 토크 약함, 떨림 |
| 3 | 각도 명령 무시 — cur가 특정 값(약 ±3.1 rad ≈ 180°)에 고정, 양방향 모두 무반응 |
| 4 | 수동 제어 스크립트에서 tilt 표시각이 −200° 등 비정상 값으로 시작 |
| 5 | 전원 재인가 후에도 자세가 90° 밖이면 재발 |

## 3. 원인 분석

### 3.1 근본 원인: 정렬(align) 시점의 자세가 유효 범위 밖

- 이 모터(STM32 FOC BLDC + 절대 자기 엔코더)는 `R` 명령 또는 전원 인가 시 **그 시점의 자세를 기준으로 센서 정렬**을 수행한다.
- tilt가 90°를 넘어 뒤집힌 자세(예: 150~180°+, 실측 약 164°)에서는 다음 중 하나 또는 둘 다 발생 (원격 진단으로 최종 구분은 못함 — 단, **둘 다 90° 초과 자세가 전제**):
  - **정렬 오류**: 엔코더 보고 프레임이 ±2π(±360°) 어긋나게 잡힘(−200° 등 이상값), FOC 센서 방향/오프셋이 잘못 캘리브레이션되어 명령과 반대로 반응·토크 약화
  - **기구 걸림**: 2회전 스핀으로 케이블이 감겨 tilt가 물리적으로 구속 → 양방향 모두 명령 무반응
- 한 번 프레임이 어긋나면, 절대 각도 기반 램프 이동이 **어긋난 프레임 기준으로 계산**되어 최대 2회전짜리 이동 명령이 만들어짐 → 다회전 폭주 재생산.

### 3.2 유발 경로 (이번 사례)

1. 저장위치 파일(`position.txt`)이 `0 0 0`으로 설정됨 — **tilt 0은 엔코더 랩(wrap) 경계**로, 부팅 복원 램프가 ±2π 프레임을 타기 쉬운 지점 (기존에 확인된 위험, TILT_SAVE_MIN=0.1 완충이 있는 이유)
2. onvif 재기동 → 위치복원 램프가 어긋난 프레임에서 계산됨 → **tilt 2회전 스핀**
3. 스핀으로 tilt가 90° 밖 자세로 이탈
4. 그 자세에서 `R` 재정렬/전원 재인가 반복 → 잘못된 정렬 고착 (전원을 다시 넣어도 자세가 밖이면 소용없음)

### 3.3 왜 각도제한 버전으로도 못 막았나 (핵심)

- 당시 적용된 onvif는 각도제한(rangeonly) 빌드였고, **클램프는 정상 작동했다** — 부팅 복원 포함 모든 명령이 0~90° 안의 목표값이었음.
- 그러나 소프트웨어 각도제한은 **"명령 공간"만 제한**하고 **"물리 자세"는 건드리지 못한다.** 센서 정렬은 소프트웨어가 올라오기 전, 전원 인가/리셋 시점의 물리 자세로 잡히는데, 그 자세가 이미 90° 밖이면 프레임이 어긋난 채 시작된다.
- 어긋난 프레임에서는 **명령 공간에서 합법인 "0~90° 명령"이 물리적으로는 2회전 이동으로 번역**된다 — 명령은 합법, 실제 움직임은 폭주.
- 요약: **각도제한 버전은 "잘못된 명령"은 막지만 "잘못된 자세에서 시작"은 못 막는다. 후자가 이번 장애이며, 물리 스토퍼가 유일한 근본 해결인 이유.**

### 3.4 구조적 배경

- **tilt에 기구적 하드스톱이 없어** 90° 초과·다회전이 물리적으로 가능했음 (케이블 꼬임 위험 포함)
- 해당 유닛은 스톨가드 없는 rangeonly 빌드 운용 중 → 소프트웨어 폭주 방어망도 부재
- pan 축은 별개의 하드웨어 결함(명령 미추종·드리프트) 보유 — 본 건과 무관하나 증상 파악을 어렵게 함

## 4. 조치 내용

### 4.1 물리 (근본 해결)
- **tilt 90° 초과 구간을 기구적으로 차단하는 물리 스토퍼 설치** ← 핵심 조치
  - 효과: 어떤 상황에서도 정렬이 유효 범위(0~90°) 안에서 수행됨 → 프레임/정렬 오류 원천 차단, 다회전·케이블 꼬임 불가

### 4.2 소프트웨어 (대증 + 재발 방지)
- onvif_srvd **정지 + 자동시작 해제**(disable) — pan 하드웨어 점검 전까지 유지
- 폭주 상태 즉시 해소 절차 정립: `R` 전송(정렬+토크 해제) → 유효 자세 확보 → 전원 재인가
- 저장위치 `0 0 0` 사용 금지 재확인 — tilt 저장/주차는 **0.1 rad(≈6°) 이상**
- 수동 제어 도구 정비 (`/home/poe/edge/`):
  - `ptz_key.py` — 방향키 조그. 검증된 pantilt.py 레시피와 동일: `R → 1s → S → 1s` 초기화, **값이 연속으로 변하는 T 스트림**만 사용(이 MCU는 동일값 반복·단발 T로는 구동 불가), 종료 시 `R`(토크 해제). 각도 제한 pan ±135° / tilt 0~90° 내장, 경계 자동 정지
  - `ptz_cont.py` — 좌표 입력식 연속 이동, `ptz_move.py` — 단발 이동

### 4.3 검증
- 물리 스토퍼 설치 후 pantilt.py 스윕 정상 동작 확인 (사용자)
- tilt 정렬·방향 정상 복귀

## 5. 재발 방지 수칙

1. **정렬(R/전원 인가)은 반드시 tilt 0~90° 자세에서** — 이제 스토퍼가 기구적으로 보장
2. tilt 저장·주차 위치는 0.1 rad 이상 (랩 경계 회피)
3. 각도 제한은 소프트웨어(범위 클램프) + 물리(스토퍼) 이중으로 유지
4. 설치/조립 시 tilt 가동범위와 스토퍼 위치 확인을 체크리스트에 포함
5. 이 MCU 제어 시: 단발 큰 T 금지, 연속 램프 스트림만 사용, arming은 `R→1s→S→1s` 벤더 타이밍 준수
