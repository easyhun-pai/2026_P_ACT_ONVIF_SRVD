**현재 결론:** 남은 떨림(ISSUE-02)은 ONVIF 문제가 아니다. ONVIF는 필수 기동 명령(R→S)을 부팅마다 1회, 같은 타이밍으로 보낸다.
떨림은 그 뒤 모터 보드가 스스로 0,0으로 이동하는 과정(전원 OFF 동안 처진 틸트를 들어 올리는 구간)에서 난다.

최신 펌웨어 장비에 같은 기동 명령(R→S)을 보낸 비교 시험에서 **떨림이 없었다**(11/02).

## ISSUE-01 · 부팅 중 R/S 중복 전송 — 해결

**현상:** 부팅 직후 약 7초간 모터 떨림. onvif disable 시 2초로 줄었으나 남음.

**원인:** NetworkManager dispatcher(`90-onvif-restart`)가 `lo`/`eth0`/`eth1` 이벤트마다 IP 변화와 무관하게 `systemctl restart onvif_srvd` 실행.
onvif_srvd는 기동마다 모터에 `R`(MCU 재부팅) → 1초 → `S`(기동)를 보내므로, 정렬이 끝나기 전에 R이 반복 투입됨.

**조치 (ptz018 반영, 백업 `/home/ptz/edge/_backup_vibfix_20261027/`):**

| 파일 | 변경 |
|---|---|
| `/etc/NetworkManager/dispatcher.d/90-onvif-restart` | `lo` 무시, ONVIF 사용 IP가 실제로 바뀐 경우에만 `try-restart` |
| `/home/ptz/edge/onvif_start.sh` | 사용 IP를 `/run/onvif_srvd.ip`에 기록, `--detect` 옵션 |
| `onvif_srvd.service` | `Wants/After=network-online.target` (drop-in `10-wait-network.conf`) |

**결과:** 부팅당 onvif 기동 1회. 다수 콜드부팅/재부팅, IP 변경 테스트에서 들썩 1회(0,0 이동), 떨림 없음 확인.
이후 SW 업데이트(10/29)에도 이 수정은 그대로 유지되고 있음(근거 3).

### SW 원인 배제 근거

**근거 1. 떨린 부팅과 안 떨린 부팅의 Pi 명령이 동일.**
읽기 전용 로거로 모터 MCU 출력을 기록하면 MCU가 받은 명령을 역으로 확인할 수 있다
(`R` → 재부팅 배너, `S` → `MOT: Init`, `T` → `Target angle: ...`).

| 부팅 (11/02) | R 수신 | S 수신 | 토크 인가 | Ready | 부팅 중 T | 관찰 |
|---|---|---|---|---|---|---|
| 50cedda3 | 8.8s | ~9.7s | ~10.2s | 10.8s | 0 | 떨림 없음 |
| a4d711ee | 8.7s | 9.8s | 10.3s | 10.8s | 0 | 떨림 6~7초 |
| b7b47c66 | 8.70s | 9.72s | 10.23s | 10.73s | 0 | 떨림 약 10초 (틸트 들림과 동시) |

(리눅스 부팅 기준 경과초, 전원 인가 후 약 8초가 0초. 10/30·11/02 오전 부팅도 동일 시퀀스 ±0.1초.)

**근거 2. 명령이 없으면 움직임도 없고, 명령은 1회뿐 (10/27).**
onvif 기동을 완전히 차단하면 모터 움직임이 전혀 없음. 움직임의 계기는 필수 기동 명령 `S`이며,
기동 이후의 이동 방식(가감속·토크·안착)은 MCU 펌웨어가 결정한다. 제작사 코드 주석: *"S always drives the axis to 0."*

**근거 3. SW 업데이트가 모터 명령 경로를 바꾸지 않음.**

| 항목 | 10/27 (떨림 없음) | 10/29 이후 (떨림) |
|---|---|---|
| onvif_srvd 바이너리 | md5 `448443cd` | `448443cd` (동일) |
| 부팅 중 onvif 기동 | 1회 | 1회 |
| dispatcher | `b3402ad2` | `b3402ad2` (동일), 부팅 7회 모두 "재시작 생략" |
| 시리얼 쓰기 프로세스 | onvif_srvd만 | onvif_srvd만 (로거는 읽기 전용) |
| 시리얼 설정 | — | raw, echo off |

**근거 4. 전원에 따라 떨림 길이가 달라짐.** 명령은 전원 종류와 무관하게 같으므로, 토크 여유에 따른 하드웨어/펌웨어 특성이다.
Pi 전압 저하 기록 없음(`throttled=0x0`, 5V 정상).

**근거 5. 떨림이 MCU 자체 이동 구간과 일치.** 토크 인가 후 MCU가 스스로 틸트를 0으로 들어 올리는 동안 떨림. 이 구간에 Pi 명령 없음.

## ISSUE-03 · R/S 후 위치 불일치 — 미착수

- R/S 후 MCU는 0,0으로 이동하지만 ONVIF는 `position.txt`(예: pan 11.9°, tilt 65.2°)를 현재 위치로 믿는다.
- 첫 상대 이동 명령 시 예상과 다른 위치로 이동할 수 있다.
- 대응안: 기동 후 position.txt를 0,0으로 초기화하거나, 기동 후 저장 위치로 명시 이동. 값 없는 `T` 조회로 실제 각도를 읽어 동기화하는 방안도 가능.

## ISSUE-04 · DHCP 미응답 시 내부 IP로 onvif 기동 — 관찰

- 11/02 부팅 1회: 링크 1Gbps 정상, DHCP 응답 3분 이상 없음 → 재연결 후 2초 만에 정상 할당. **허브/DHCP 서버 측 추정.**
- 이때 onvif는 network-online 대기(약 60초) 후 eth1 내부 IP(192.168.1.10)로 기동, wsdd는 5초마다 실패 재시작(29회).
- 이후 DHCP가 성공하면 dispatcher가 IP 변경으로 보고 onvif 재시작 → R/S 1회 추가(들썩 1회 추가).
- 개선 여지: 기동 IP 선택 시 eth1(내부망) 제외.

**11/02 저녁 추가 (검토 의견 반영 최종 빌드, md5 `45ea6988`)**

- 검토 의견: "모터 드라이버가 꺼졌다 켜졌다 하는 느낌" → 전원·PoE 안정 전에 두 모터가 동시에 힘을 쓰는 상황일 수 있어 다음을 반영.
- 콜드부팅 시 **부팅 30초 후 기동** (`PTZ_ARM_DELAY_S`).
- **현재 자세 그대로 기동**: 미기동 MCU는 `S` 전 `T`를 무시하지만, `S` 직후부터 현재 자세를 20ms마다 보내면 Ready 순간 그 자리를 잡는다(실측). 각도 = wrap(원시각 − 저장된 offset).
- 이동 명령 없음(재부팅·재시작은 명령 0건), 기동 전 단발 이동 요청은 기동 후 실행.
- **자동 재시도 없음** — 이상 시 `PTZ-ALERT` 로그만. 기동 후 30초 상태 기록(`PTZ-MON`), 운영 중 5초 주기 감시.
- 결과(콜드부팅 1회): uptime 30.1초에 `S`, 처진 자세 그대로 유지, **떨림·움직임 없음**. 기동 후 "웅" 소리는 원본에서도 나던 소리(문제 아님).

**콜드부팅 떨림 해석:** 장비에는 롤 방향 모터가 없다. 기동 직후 처진 고개를 들어 올리는 동안 모터 헌팅이 헤드·브래킷 유격을 통해 롤 방향 진동으로 나타나는 것으로 추정.
